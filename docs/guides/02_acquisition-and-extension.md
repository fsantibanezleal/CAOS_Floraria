# Acquire or extend the collection

Run python data-pipeline/run.py all for the locked corpus. --offline uses verified cache; --root PATH selects the entire sandbox input/output root. Seed it with copies of data/sources and the verified data/raw/assets cache before an offline run; it is not merely an output path. verify checks existing canonical files without fetching or rewriting. Read --help for stage flags.

## Add a compatible specimen

1. Establish authoritative item source and redistribution rights.
2. Acquire supported self-contained GLBs; record URL/bytes/SHA-256/variant/credit.
3. Inspect nodes, meshes, materials, indices, extensions and scale evidence.
4. Add bilingual metadata/references without inventing hidden segmentation.
5. Validate/export in a sandbox and inspect actual renders.
6. Update canonical artifacts, manifest, attribution, cases and changelog together.

Unsupported inputs are rejected. Missing physical scale remains unknown. A second fidelity file is not a second biological sample.

Authored models require their own component hierarchy and references. Each selected part needs text; every investigation step needs a valid view. Lifecycle additions must state where illustration stops and prediction would require new evidence.

See [contracts](../data-contract.md) and [validation](../architecture/05_validation.md).
